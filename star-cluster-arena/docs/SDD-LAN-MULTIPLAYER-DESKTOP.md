# 星团大作战：局域网联机与 Windows 桌面版 SDD

- 文档状态：实施基线
- 目标版本：3.0.0-lan
- 最后更新：2026-08-20
- 主源码：`star-cluster-arena/`
- 桌面成品目录：`../star-cluster-arena-desktop/`

## 1. 目标与边界

本项目在不修改仓库根目录 `ball-arena.html` 的前提下，为现有前后端版本增加一个完整的局域网联机纵切面，并将同一套前端、后端和联机协议封装为可安装、可便携运行的 Windows 桌面游戏。

首个可玩版本必须完成：

1. 原有十种单机模式保持可用。
2. 主界面提供“联机测试”入口。
3. 玩家可创建房间、自动发现局域网房间、使用六位房间码加入、准备并由房主开局。
4. 一局支持 2～8 个真人连接，缺额可由 AI 补齐。
5. 首发联机规则为自由模式，包含移动、食点、质量衰减、分裂、吐球、玩家吞噬、排行榜、死亡与复活。
6. 游戏状态由房主电脑内的服务器权威裁定，客户端只发送输入并渲染快照。
7. 连接中断后 AI 临时接管；在宽限期内允许使用恢复令牌重连。
8. 同一 Windows 程序既可创建房间，也可加入房间。
9. 构建产生安装程序和便携 ZIP，成品只写入顶层 `star-cluster-arena-desktop/`。

首发版本不包含：公网匹配、账号登录、云存档、付费系统、语音聊天、100 名真人同局、主机迁移、其他九种模式联机化。上述能力不得通过协议设计被永久阻断。

## 2. 版本关系

| 版本 | 角色 | 维护策略 |
|---|---|---|
| `ball-arena.html` | 历史单文件离线版 | 冻结，不修改 |
| `star-cluster-arena/` | 唯一游戏主源码、浏览器前后端版 | 持续维护 |
| `star-cluster-arena-desktop/` | Windows 构建产物 | 自动生成，不手工维护源码 |

桌面封装源码位于 `star-cluster-arena/desktop/`，不得复制一份前端或后端形成分叉。Electron 构建时将主项目资源打进应用包。

## 3. 用户流程

### 3.1 创建房间

1. 玩家启动网页前后端版或桌面版。
2. 点击“联机测试”。
3. 输入昵称，点击“创建房间”。
4. 本机房间服务返回房间码和房主令牌。
5. 客户端连接本机 WebSocket，进入等待大厅。
6. 房间通过 UDP 在局域网周期广播。
7. 所有玩家准备后，房主点击“开始游戏”。

### 3.2 加入房间

1. 联机大厅每秒读取本机发现缓存。
2. 玩家直接点击房间卡片，或输入六位房间码。
3. 客户端连接房主 WebSocket，完成协议版本握手。
4. 玩家准备，等待房主开局。

### 3.3 异常路径

- 自动发现失败：显示可操作错误，并允许刷新发现列表。
- 房间码不存在：明确提示“当前局域网未发现该房间”。
- 版本不兼容：拒绝加入并显示客户端/服务器协议版本。
- 房间已满或已开始：拒绝加入并保持大厅可用。
- 对局中断线：服务器保留玩家实体 15 秒并由 AI 接管；客户端使用恢复令牌自动重连。
- 房主程序退出：服务器消失，所有玩家返回联机大厅并看到“房主已离线”。

## 4. 组件架构

```text
Electron 主进程（仅桌面版）
  ├─ 启动内置 Node HTTP/WebSocket/UDP 服务
  ├─ 选择可用动态端口
  ├─ 创建安全 BrowserWindow
  └─ 退出时关闭所有网络资源

浏览器渲染层
  ├─ 原有单机 index.html + game.js
  └─ multiplayer.html
      ├─ 房间大厅
      ├─ WebSocket 输入与重连
      ├─ 快照插值
      └─ Canvas 联机渲染

Node 服务
  ├─ HTTP 静态资源与 REST API
  ├─ WebSocket 协议入口
  ├─ RoomManager
  ├─ AuthoritativeSimulation
  └─ LanDiscovery（UDP 广播与发现缓存）
```

## 5. 服务端设计

### 5.1 网络频率

- 权威模拟：20 Hz 固定步长。
- 玩家输入：客户端最多 20 Hz；服务端保存每名玩家最新输入。
- 世界快照：10 Hz；重要大厅和生命周期事件立即发送。
- 客户端渲染：显示器刷新率驱动，通过前后快照插值。
- 心跳：5 秒 ping，15 秒无活动视为断开。

频率作为常量集中管理，后续压测后才允许调整。

### 5.2 房间状态机

```text
LOBBY → RUNNING → FINISHED → CLOSED
```

- `LOBBY`：允许加入、准备、修改有限设置。
- `RUNNING`：拒绝新玩家；允许持恢复令牌的原玩家重连。
- `FINISHED`：广播结果，短暂保留后回到大厅或关闭。
- `CLOSED`：释放定时器、连接和发现记录。

### 5.3 权威原则

服务端不接受客户端上报的坐标、质量、击杀、排名或冷却结果。客户端输入仅包括归一化目标方向和动作序号。所有实体 ID、随机数、碰撞、吞噬、复活与结算均由服务端生成。

首发模拟采用服务器种子伪随机数，便于重现测试。世界快照只包含渲染所需字段，不泄露令牌和内部 AI 状态。

### 5.4 空间与实体

- 世界尺寸：5200 × 5200。
- 食点目标：按真人和 AI 数量计算，限制在 480～900。
- 真人上限：8。
- AI 可配置：0～12，默认补到 8 个参与者。
- 单组分身上限：16。
- 服务端使用空间哈希减少食点和细胞碰撞候选。
- 客户端首版接收完整快照；协议保留区域兴趣管理字段，为扩容做准备。

## 6. 协议

协议版本常量：`sca-lan-v1`。所有消息使用带 `type` 的 JSON；结构错误、超长消息和未知高频消息必须拒绝或限流。

### 6.1 客户端到服务器

| 消息 | 关键字段 | 说明 |
|---|---|---|
| `join` | `name`, `resumeToken?`, `hostToken?`, `protocol` | 加入或恢复会话 |
| `ready` | `ready` | 设置准备状态 |
| `start` | 无 | 仅房主可用 |
| `input` | `seq`, `dx`, `dy`, `split`, `eject` | 最新控制输入 |
| `ping` | `clientTime` | 延迟测量 |

### 6.2 服务器到客户端

| 消息 | 关键字段 | 说明 |
|---|---|---|
| `welcome` | `playerId`, `resumeToken`, `host`, `room` | 会话建立 |
| `lobby` | `room`, `players`, `settings` | 大厅全量状态 |
| `match-start` | `seed`, `world`, `serverTime` | 开始加载对局 |
| `snapshot` | `tick`, `serverTime`, `groups`, `foods`, `ejected` | 权威快照 |
| `event` | `event`, `data` | 击杀、复活、结算等 |
| `pong` | `clientTime`, `serverTime` | 延迟测量 |
| `error` | `code`, `message` | 可显示错误 |

消息体默认上限 64 KiB；快照由服务端发送，不受客户端消息上限影响。若 JSON 快照成为瓶颈，再在 `v2` 引入二进制编码，不能在 `v1` 中静默改变结构。

## 7. 局域网发现

- 使用 Node `dgram` 在 UDP 25556 端口监听，启用地址复用。
- 有开放房间时，每 1500 ms 向局域网广播一条带签名字段和协议版本的短 JSON。
- 接收端以 UDP 数据包来源地址作为房主地址，不信任广播正文声明的 IP。
- 发现记录 5 秒未刷新即过期。
- HTTP `GET /api/lan/rooms` 返回本机房间与发现缓存的合并、去重结果。
- 房间码只在已发现的房间集合中解析，不将房间码设计为 IP 编码。
- 自动发现被防火墙或 AP 隔离阻止时，首发版显示诊断信息；二维码/公网信令属于后续范围。

## 8. HTTP 与安全

新增 API：

- `GET /api/lan/status`
- `GET /api/lan/rooms`
- `POST /api/rooms`
- `GET /api/rooms/:code`
- `DELETE /api/rooms/:code`（要求房主令牌）
- `GET /ws?room=ABC123`（WebSocket Upgrade）

安全要求：

- 房间码、房主令牌和恢复令牌使用加密安全随机数。
- 昵称去控制字符、去首尾空白、长度限制 1～16。
- 创建房间和握手进行每 IP 速率限制。
- 校验 Origin；桌面本机来源、同源网页和明确允许的局域网来源可连接。
- CSP 只扩展联机页面所需的 `ws:`/`wss:`，不启用远程脚本。
- Electron 使用 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`。
- 不在渲染进程暴露任意文件系统或进程执行接口。

## 9. 桌面封装

### 9.1 运行方式

Electron 主进程通过导出的 `startServer({ host: "0.0.0.0", port: 0 })` 启动服务，等待获得实际端口后打开 `http://127.0.0.1:<port>/`。服务以子/工具进程隔离时不得出现控制台窗口。

单实例锁防止误开多个服务；第二次启动聚焦现有窗口。关闭最后一个窗口时先优雅关闭 HTTP、WebSocket、房间和 UDP 套接字。

### 9.2 构建产物

Electron Forge 输出目录固定为仓库顶层 `star-cluster-arena-desktop/`：

```text
star-cluster-arena-desktop/
├─ 星团大作战-安装程序.exe                 可直接上传的安装版
├─ 星团大作战-便携版-<version>-win-x64.zip 可直接上传的便携版
├─ 星团大作战-win32-x64/                   解包后的应用（本地验证用）
└─ make/                                      Electron Forge 中间产物
   ├─ squirrel.windows/x64/星团大作战-安装程序.exe
   └─ zip/win32/x64/星团大作战-便携版-<version>.zip
```

成品目录是可重新生成的构建输出。不得在其中存放唯一源码或手工资料。

### 9.3 发布注意事项

- 未配置代码签名证书时，构建仍可完成，但 Windows SmartScreen 可能警告。
- 正式公开发布前配置证书和时间戳，不把证书密码提交仓库。
- 安装版创建开始菜单与桌面入口，并支持卸载。
- ZIP 必须整体分发；不得只复制其中的 EXE。
- 首次创建房间可能触发 Windows 防火墙提示，UI 应提前说明仅需允许专用网络。

## 10. 可观测性与错误处理

- 服务日志写入桌面应用数据目录；浏览器开发版继续输出控制台。
- 日志不得记录房主令牌和恢复令牌。
- `/api/health` 增加房间数、连接数和协议版本，不暴露玩家身份。
- 联机 UI 显示连接状态、往返延迟、服务器 tick、重连倒计时和可读错误。
- 快照积压时丢弃旧快照，只保留最新状态，避免浏览器消息队列无限增长。

## 11. 测试规范

### 11.1 静态检查

- 所有 `.mjs`/`.js` 执行 `node --check`。
- HTML 中引用的本地资源必须存在。
- SDD、README、构建脚本中的路径一致。

### 11.2 单元测试

- 协议字段、昵称、房间码与限流校验。
- 房间状态转换、房主权限、准备条件、满员拒绝、恢复令牌。
- 固定种子下模拟结果可重复。
- 质量、坐标、半径均为有限非负数；实体数量不超过上限。
- 分裂、吐球、吞噬、死亡、AI 接管与复活规则。
- 局域网发现包解析、去重与超时。

### 11.3 集成测试

- 随机端口启动真实 HTTP/WebSocket 服务。
- 创建房间，连接房主和客人，准备并开始。
- 发送输入后收到递增 tick 的快照。
- 非房主无法开局；错误协议、错误房间码和超员连接被拒绝。
- 断线后使用恢复令牌重新取得相同玩家 ID。
- 服务关闭后没有残留计时器或监听端口。

### 11.4 桌面与构建测试

- Electron 开发启动后健康检查成功、窗口标题正确、无 Node 集成。
- 使用临时用户数据目录完成无交互桌面冒烟测试。
- `electron-forge package` 成功，打包目录包含前端、后端和桌面入口。
- `electron-forge make` 生成 Squirrel 安装程序和 Windows ZIP。
- 对构建产物执行文件存在性、大小非零、ZIP 可列举、安装器 PE 头检查。

### 11.5 人工验收

至少两台 Windows 设备在同一 Wi-Fi/有线网络：

1. 双方仅安装同一个桌面包。
2. A 创建房间，B 在 3 秒内看到房间。
3. B 点击加入，无需输入 IP。
4. 双方准备、开局，并互相看到移动、分裂、吐球和质量变化。
5. B 断网后 AI 接管；恢复网络后自动重连。
6. A 退出后 B 收到房主离线提示并返回大厅。
7. 重复测试 Windows 防火墙允许与拒绝两种路径。
