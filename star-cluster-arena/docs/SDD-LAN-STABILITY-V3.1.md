# 星团大作战：局域网联机稳定性 SDD v3.1

状态：实施基线

日期：2026-08-20

适用范围：`star-cluster-arena/` 前后端源码版与 Windows 桌面封装版

成品目录：`../star-cluster-arena-desktop/`

## 1. 背景与问题审计

本轮不增加新玩法，目标是让现有局域网联机从“偶尔能用”变成可诊断、可恢复、双向一致的功能。

已确认的问题如下：

1. 当前测试机上的便携版程序存在 TCP/UDP 专用网络入站允许规则，但安装版 `app-3.0.0/StarClusterArena.exe` 存在 TCP/UDP 专用网络入站阻止规则。阻止入站的一方可以作为客人发起出站连接，却无法稳定作为房主接受连接，形成明显的方向差异。
2. 桌面版每次启动使用随机 TCP 端口。虽然协议允许随机端口，但它增加了诊断难度，也不利于形成稳定的防火墙行为。
3. UDP 发现只有周期性广播，没有主动查询；进入大厅后可能必须等待下一个广播周期。
4. 当最后一个房间关闭时，发现服务不发送空房间公告，其他电脑只能等缓存超时。
5. 同一房间只向客户端暴露一个地址。多网卡、虚拟网卡或链路本地地址参与广播时，客户端可能选中不可达地址。
6. WebSocket 连接没有明确超时，也没有候选地址回退；一次不可达连接会长时间停留。
7. 多次连接尝试之间没有代际隔离，旧连接迟到的 `close` 事件可能干扰新连接。
8. 玩家主动退出和网络意外中断走同一条路径，客人会以“等待重连”状态保留 15 秒。
9. 房间变化没有立即触发公告；创建、加入、退出和关闭的可见性依赖固定周期。

## 2. 目标与非目标

### 2.1 目标

- 同一专用局域网内，双方网络权限正确时，房间应在 2 秒内出现。
- 点击房间后，正常局域网连接应在 3 秒内完成。
- 首选地址不可达时，客户端自动尝试其他候选地址，不要求玩家输入 IP。
- A 建房/B 加入和 B 建房/A 加入采用完全相同的流程并通过同一组测试。
- 主动退出的客人应在 1 秒内从房间列表消失。
- 主动退出的房主应立即关闭房间；远端大厅应在 2 秒内移除房间。
- 意外断线仍支持恢复：等待房间 5 秒，对局中 15 秒。
- 防火墙阻止、发现端口不可用、没有有效局域网地址等情况必须显示可读诊断。
- 桌面版优先使用固定 TCP 端口 `25555`，仅在本机端口被占用时回退到系统分配端口。

### 2.2 非目标

- 不实现公网匹配、NAT 穿透、云中继或账号系统。
- 不绕过企业/校园网的客户端隔离策略。
- 不静默创建、删除或覆盖 Windows 防火墙规则。
- 不取消对局中的断线恢复与 AI 接管。

## 3. 成功指标

| 指标 | 合格线 |
|---|---:|
| 主动查询后的房间发现延迟 | `<= 2 s` |
| 正常地址 WebSocket 加入延迟 | `<= 3 s` |
| 单地址失败判定时间 | `<= 1.8 s` |
| 候选地址最大尝试数 | `3` |
| 主动退出玩家移除延迟 | `<= 1 s` |
| 主动关闭房间远端移除延迟 | `<= 2 s` |
| 等待房间异常断线保留 | `5 s` |
| 对局异常断线恢复窗口 | `15 s` |
| 自动化测试 | 全部通过，无残留端口/计时器 |

## 4. 稳定发现协议

继续使用兼容标识 `SCA-LAN`、发现版本 `1` 和联机协议 `sca-lan-v1`。新增字段均为向后兼容字段。

### 4.1 公告包

```json
{
  "magic": "SCA-LAN",
  "version": 1,
  "protocol": "sca-lan-v1",
  "kind": "announce",
  "instanceId": "uuid",
  "port": 25555,
  "addresses": ["192.168.0.15"],
  "rooms": []
}
```

- `rooms` 允许为空。空列表表示该实例当前没有等待中的房间。
- `addresses` 只包含非回环、非链路本地的 IPv4 地址，最多 8 个。
- UDP 数据包的真实来源地址始终加入候选地址，不信任数据包声明的公网或无效地址。

### 4.2 查询包

```json
{
  "magic": "SCA-LAN",
  "version": 1,
  "protocol": "sca-lan-v1",
  "kind": "query",
  "instanceId": "uuid"
}
```

- 客户端进入大厅、点击刷新和使用房间码时发送查询。
- 收到查询的实例在 200 毫秒限流保护下立即发出公告。
- `POST /api/lan/probe` 发出查询，等待 450 毫秒收集响应后返回房间列表。

### 4.3 缓存一致性

- 缓存键为 `instanceId + servicePort + roomCode + address`。
- 收到同一实例的新公告后，立即移除该实例本次公告中不存在的房间。
- 完全失联的实例仍以 5 秒 TTL 清除。
- 房间管理器发生创建、加入、退出、开始或关闭变化时立即公告，不只依赖周期定时器。

## 5. 地址选择和连接回退

每个房间从 API 返回：

```json
{
  "endpoint": "ws://192.168.0.15:25555/ws?room=ABC234",
  "endpoints": [
    "ws://192.168.0.15:25555/ws?room=ABC234",
    "ws://192.168.0.16:25555/ws?room=ABC234"
  ]
}
```

排序规则：

1. 与本机任一有效 IPv4 位于同一子网的地址。
2. RFC1918 私有地址。
3. 其他有效单播 IPv4。
4. 回环、组播、广播、`0.0.0.0` 和 `169.254.0.0/16` 不作为远端候选。

客户端流程：

1. 对候选地址去重，最多保留 3 个。
2. 每个地址设置 1.8 秒“连接并收到 welcome”超时。
3. 失败后关闭旧 socket，再尝试下一个地址。
4. 每次加入过程分配递增代际编号；旧 socket 的 `open/message/error/close` 事件不得改变当前 UI。
5. 所有候选失败后，显示失败阶段、尝试地址数量和防火墙提示。

## 6. 房间与玩家生命周期

### 6.1 主动退出

客户端先发送：

```json
{ "type": "leave" }
```

然后执行 WebSocket 正常关闭。

- 客人主动退出等待房间：立即从 `room.players` 删除并广播大厅状态。
- 客人主动退出对局：连接标记为永久离开，模拟中的星团由 AI 接管，不再接受原恢复令牌。
- 房主主动退出：无论等待还是对局，立即关闭房间并通知其他玩家。
- 连接的后续 `close` 事件必须幂等，不得重复安排恢复计时器。

### 6.2 意外断线

- 等待房间：玩家显示“等待重连”，最多保留 5 秒。
- 对局中：保留 15 秒恢复令牌，期间 AI 接管。
- 等待房间房主断线 5 秒仍未恢复：关闭房间。
- 所有恢复计时器在房间关闭或服务退出时清理。

### 6.3 房间码会话

- 主动退出后删除本次 `sessionStorage` 恢复信息，避免再次加入时恢复一个已经离开的身份。
- 意外断线不删除恢复信息。
- 恢复令牌只能恢复同一房间、同一服务端点中的身份。

## 7. 端口与双向建房

- 桌面版依次尝试 TCP `25555`、`25557`，两者都占用时使用系统动态端口。
- UDP 发现固定使用 `25556`，启用地址复用；绑定失败不阻止单机游戏，但联机大厅必须显示错误。
- 公告始终携带实际 TCP 端口。
- 不假设某台电脑固定为房主；任意实例均可同时发现远端房间并创建自己的房间。
- 本机创建的房间和远端发现房间按 `instanceId + roomCode` 区分，避免仅按房间码错误覆盖。

## 8. 防火墙与网络诊断

桌面版启动时只读检查当前 `process.execPath` 对应的 Windows 入站规则，结果为：

- `allowed`：专用网络 TCP/UDP 入站均允许。
- `blocked`：存在启用的入站阻止规则。
- `missing`：没有匹配规则，首次联机可能出现系统提示。
- `unknown`：检查失败或非 Windows 系统。

诊断结果通过 `/api/lan/status` 和 `/api/lan/rooms` 返回，并在联机大厅展示。

- `blocked` 时创建房间前显示明确警告：当前电脑无法可靠作为房主。
- `missing` 时提示在 Windows 弹窗中只允许“专用网络”。
- 桌面版提供“打开 Windows 防火墙设置”按钮；按钮只打开系统设置，不自动更改规则。
- 客人连接失败时优先提示检查房主电脑，而不是只提示客人自己的网络。
- 日志记录实际 TCP 端口、有效 IPv4、UDP 状态和防火墙诊断，但不记录令牌。

## 9. API 变化

- `GET /api/lan/status`：增加 `addresses`、`servicePort`、`firewall`、`preferredPort`。
- `GET /api/lan/rooms`：房间增加 `instanceId`、`endpoints`；保留单数 `endpoint` 兼容旧客户端。
- `POST /api/lan/probe`：主动查询并在短暂收集窗口后返回最新房间。
- `POST /api/rooms`：返回本机诊断摘要；不因诊断失败拒绝建房。
- WebSocket 新增客户端消息 `leave`。

## 10. UI 状态规范

大厅连接状态必须区分：

- 联机服务正常
- 正在主动扫描
- 未发现房间
- UDP 发现不可用
- 本机防火墙阻止作为房主
- 正在尝试第 N/M 个房主地址
- 房主不可达：可能由房主防火墙或网络隔离导致

房间列表显示来源、地址候选数量和最近更新时间。按钮在连接期间禁用，防止并行加入。

## 11. 测试矩阵

### 11.1 单元测试

- 查询包与公告包解析、非法地址过滤、同实例空公告清理。
- 同子网地址排序、候选去重和最多 3 个限制。
- UDP 绑定失败可诊断且不残留 socket。
- `leave` 消息解析。
- 主动退出立即删除；异常断线分别使用 5 秒和 15 秒。
- 房主主动退出关闭房间；重复 close 幂等。

### 11.2 集成测试

- 启动两个服务实例，A 建房/B 加入，然后反向 B 建房/A 加入。
- 首个候选端点不可达时回退到第二个端点。
- 客人主动退出后，房主在 1 秒内收到不含该玩家的 lobby。
- 房主退出后，客人收到 `host-left` 并且 REST 房间不存在。
- 主动 probe 能发现公告；空公告立即移除房间。
- 服务关闭后 TCP、UDP 和计时器全部释放。

### 11.3 界面验收

- 两个本地服务模拟两台电脑，分别打开独立联机大厅。
- A 创建、B 自动发现、B 加入、B 退出，A 玩家列表立即更新。
- B 创建、A 自动发现、A 加入，验证方向互换。
- 注入错误首选地址，确认 UI 显示回退而不是长期卡住。
- 检查页面控制台无未处理异常。

### 11.4 真机验收

至少两台 Windows 电脑处于同一专用 Wi-Fi/有线网络：

1. 两端安装 v3.1，确认防火墙诊断不是 `blocked`。
2. A 创建、B 加入、退出；再由 B 创建、A 加入、退出。
3. 双方各重复 10 次，成功率必须为 100%。
4. 分别关闭其中一端 Wi-Fi，验证异常断线与恢复。
5. 将网络配置为“公用”或启用 AP 隔离，确认 UI 给出诊断而不是无限等待。
