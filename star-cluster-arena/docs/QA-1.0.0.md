# 1.0.0 发布候选验证记录

日期：2026-10-03。基线工程 v4.0 / 79f6618。验证目标与缺陷见 [SDD](SDD-RELEASE-1.0.md)。用户要求不再占用电脑前台，因此停止后续实际 UI 输入和最终包前台长测，改做后台源码 / 网络 / 压力与静态包核对。本轮按 `sca-v1.0.0-rc.1` 预发布，未完成门禁明确保留，不能据此声称稳定正式版、Steam 或真实跨城已验收。

## 条件与方法

生命周期 E2E 的静止探针临时受 debug 护盾保护，并选择仍存活的 AI 来构造观战夹具。首轮打包测试中随机阵亡会提前触发结算、干扰下一步 Esc 菜单断言；已修正这个测试竞争，不是通过忽略失败来放行。普通对局不加此护盾。

Windows x64，本机运行日志识别 NVIDIA GeForce RTX 5070 Ti / ANGLE Direct3D11、160Hz 显示目标，Electron 44.5.1；不是第二台 RTX 5060 的测量。显示器实际为 3840×2160、175% 缩放，Windows 显示输出由 AMD 核显承载。桌面模式套件顺序启动独立进程，不同时跑重 CPU 压力测试，单人 / 两客户端本机联机各 10 模式，16 秒四个采样，稳态统计使用 8–16 秒。

为避免静止的采样玩家早早被 AI 吞掉而失去有效帧，单人性能探针临时给予 debug 护盾；AI / 食点 / 物理 / 画面仍正常运行。这是性能测量，不是难度和真实玩家胜率评估。实际 UI 试玩用于检查布局、鼠标与键盘操作，不以 debug 测试代替所有手感验收。

测试过程不能操作其他原生窗口：单人失焦会按设计自动暂停，以 30 FPS 节能绘制。首轮成品长时间监测与安装器人工验收交错，导致失焦暂停、平均 47 FPS 而失败；该轮不作为有效性能样本。探针已增加 paused 与原生焦点检查，失焦即明确报告测试干扰，不自动解除暂停或放宽性能门槛。

收尾发现第二个探针缺陷：旧脚本点击隐藏的开始按钮，没有关闭主页，实际画面仍为主页叠加后台对局；屏幕外短测亦没有真实呈现压力。旧 133 FPS 数据不能作为玩家帧率证据。现改为正常「主页 → 单人大厅 → 开始」流程，断言主页 / 大厅已关闭，并默认在可见前台测量、记录原生焦点 / 尺寸 / 显示器。开始比赛函数也无条件移除主页，行为测试防止再开入口回归。失败报告仍保留，不只保存通过样本。

规则层压力使用 Node 24，固定种子、60Hz 物理、20Hz 实际发送频率，输入分裂 / 吐球 / 模式技能，逐快照检查实体有限值、正质量和目标人数。结算 E2E 通过 debug 夹具设置剩余存活者，再由原规则下一帧结算，未伪造客户端获胜事件。

## 已通过

- 最终源码检查通过：52 个关键文件、51 个脚本语法与 HTML 本地资源；全量测试 198 / 198，0 失败 / 跳过。其中包含十模式源码同源 / 第一帧一致、人口、魔王碰刺、喂刺、护盾、事件、快捷技能、胜者、暂停墙钟、重复输入、连接 / 重连、存档损坏恢复和 TLS / WSS。新增伪造匹配 Host / Origin 的 HTTP 与 WebSocket 拒绝、显式测试护盾、进入比赛移除主页、同步 / 异步日志管道关闭的回归。部分历史模拟器测试仍保留，仅同源 / release / 网络测试验证现行权威；不能把所有历史测试误称为现行服务器规则测试。
- 桌面完整流程：单人 Esc 冻结时间，暂停操作不改变分身，继续与 R 确认；限时结算 / 再开；联机 2 真人 + 98 AI，大逃杀房主出局后观战，Tab 切目标，Esc 释放输入，访客获胜，结算保持可读，4 秒后返回原房间，等待房间 Esc 退出。
- 真实 HTTPS 反向代理 + 两个 WebSocket 客户端：显式信任测试证书，创建私密房间 / 准备 / 100 人模式 / 外观同步，私密房间不进入公开列表。没有关闭 TLS 校验；证书只用于测试，不能部署生产。
- 生产依赖审计：官方 npm registry，`npm audit --omit=dev`，0 漏洞；不代表系统和所有开发工具永久无漏洞。

开发工具已升级 Forge 8.0.1 并应用兼容依赖补丁。完整开发依赖审计仍有 8 个 high 告警，均由 electron-builder 的 `@electron/get → got → http-cache-semantics` 同一上游漏洞传递，不是 8 个独立游戏漏洞。[GHSA-ch52-4w7c-c8xp](https://github.com/advisories/GHSA-ch52-4w7c-c8xp) 在本次检查时没有补丁，涉及共享 HTTP 缓存的跨用户响应泄露。这些依赖不随游戏 / 生产服务器发布；本工程也不把打包下载器作为用户共享缓存服务。不关闭审计、不用不兼容的跨主版本 override 消除告警；上游修复后须更新打包链并回归。
- 手动 Windows 试玩：1280×720 模式开始按钮可见；单人游戏运行、Esc 菜单、分钟级停留时质量 / 排名 / 时间冻结、继续与离开。
- 普通独立存档（没有 debug 护盾）桌面试玩发现并修复 LOG-01：启动命令结束后，全屏 IPC 的控制台输出曾抛出 EPIPE；修复后按钮实际进入 3840×2160 显示器的无边框全屏。闪电模式约 116 秒按原制霸条件结算，团队战实际鼠标移动、Esc 暂停在 0:42，继续后时间推进。静止玩家与有限操作不能作为真人难度 / 胜率验收；键盘分裂 / 吐球本轮未获得清晰的人工确认，不冒称通过。

## 闪屏监测

旧便携 EXE 的窗口 / 无边框全屏各 300 秒报告也受 TEST-01 的主页覆盖影响，17801 个无白样本只说明该覆盖场景，不能证明纯游戏白帧验收。最终包须重新走正常大厅进入可见对局，再分别监测两个显示模式。检测将 Electron 合成帧缩小到 64×36，近白比例 ≥ 72% 或平均通道 ≥ 220 计为疑似白帧；捕获开销与无捕获帧率分开报告，不用捕获数据冒充玩家帧率，也不据有限样本声称所有驱动永不闪屏。

## Windows 成品与安装入口

发行目标为 NSIS 引导式安装程序和完整便携 ZIP，不是只有一个下载器。已直接启动打包 EXE 与解压后的 EXE；最新便携包三轮独立进程、共九组比赛 / 显示 / 导航验证通过。显示测试使用透明测试窗口，验证按钮 / 设置的真实 IPC 和原生 fullscreen=true / false、UI 持久化值；不是新一轮人工前台试玩。三轮导航分别 51 / 52 / 51 个合成样本，无疑似白帧。该轮在用户停止前台测试指示前已启动，完成后不再启动任何桌面测试。原始最新报告：[portable-readiness-1.0.json](qa/portable-readiness-1.0.json)；[packaged-readiness-1.0.json](qa/packaged-readiness-1.0.json) 为此前未解压包记录，不冒称最新。

新增无窗口成品核对：[portable-bundle-1.0.json](qa/portable-bundle-1.0.json)。45 个运行文件逐字节与当前源码一致；包内运行元数据核对、Electron / Chromium / ws 许可与必需 DLL / 中文语言包存在。electron-builder 按设计移除构建脚本和 devDependencies，因此元数据按其预期投影核对，其他运行源码不放宽匹配。此静态核对不代替前台帧率、完整安装或跨城网络验收。

实际打开 NSIS 向导，确认当前用户 / 所有用户选择、目录页、可编辑目标与浏览按钮；将目标从默认 C 盘改为 `D:\Games\StarClusterArena` 后取消，没有点击安装，不覆盖现有程序。因此目录选择确已实测，但干净机器的完整安装 / 卸载 / 升级仍未验收。

便携 ZIP 保留 `LICENSE.electron.txt` / `LICENSES.chromium.html`；应用 ASAR 包含项目 MIT License、第三方通知和运行依赖许可。成品版本信息为 1.0.0，签名状态 NotSigned，不声称已购买代码签名。发行目录有安装 EXE、便携 ZIP、可直接启动的完整解压目录及 SHA256SUMS.txt。
