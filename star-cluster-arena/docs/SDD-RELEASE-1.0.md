# 星团大作战 · 正式产品 1.0 开发规格

日期：2026-10-03。基线：工程 v4.0.0 / 提交 79f6618。

## 目标与版本

以现有十模式共享玩法为基础，完成首次面向普通玩家的正式产品版本。旧工程 v4.0 保留为开发历史；新产品采用 `1.0.0` 版本号，最终标签拟用 `sca-v1.0.0`，避免与合集仓库其他游戏冲突。本轮未完成全部正式门禁，以 `sca-v1.0.0-rc.1` 预发布（成品构建版本为 1.0.0），不得描述为正式验收或 Steam 审核已通过。

必须保留单机与服务器执行同一份玩法代码的约束；任何数值修改同时作用于两种会话。独立单 HTML 历史版保持原状，正式开发入口是本工程。

## 交付范围

1. 实际桌面试玩与十模式行为审计：记录可复现触发、预期、严重程度和修复证据。
2. 游戏入口与操作：模式选择可快速开始、暂停可继续、退出有确认；焦点丢失停止输入；分裂/技能不得在暂停或结算时执行；新玩家获得玩法目标和键位提示。
3. 数值与公平：所有真人使用同一模式的出生基线；成长不能影响联机竞技数值；复活、护盾、分裂、喂刺、结算正确。根据模拟与试玩证据修复明显异常，不凭印象全面重写已验证模式。
4. 性能：60Hz 玩法与画面频率独立；减少服务器每物理帧全世界快照复制；使用可测量的帧耗时、带宽和渲染稳定性门槛。
5. 异地联机：保留 LAN 自动发现；增加互联网服务选择、服务状态检查、房间列表、房间码及邀请链接加入。提供公网权威服务器容器、HTTPS/WSS 反向代理和部署说明；真实公共服务需要用户提供主机/域名或有权限的部署账号。
6. 发布：Windows 安装与便携成品、校验清单、第三方许可、发布说明、开发者部署文档、Steam 上架准备说明与已知限制。

## 架构决策

公网第一阶段继续使用 Node.js 权威房间服务 + WebSocket，完整复用共享玩法。浏览器、桌面和部署服务只改变连接目的地。Steam 版本未来可在传输适配层接入 SteamNetworkingSockets/SDR；开源 GameNetworkingSockets 并不提供 Valve 中继服务权限，不把它当作无需运维的免费联机服务。

## 发布门禁

- 全量单元、真实 HTTP/WebSocket 双客户端集成测试和资源/语法检查通过。
- 十模式共享玩法、人数、关键交互、规则计时与结算有行为测试。
- 公网配置下跨 origin 房间创建、WSS 地址、邀请解析与非法地址拒绝有集成测试；不能用 localhost 测试冒充真实跨城验证。
- 十模式压力测试物理帧 P95 < 12ms，快照流量 < 2MiB/s/客户端；异常不得无界累积。
- 桌面实际试玩、开始/暂停/继续/退出、窗口切换、外部链接、装扮与联机流程通过。
- 打包 EXE 可独立启动，无 Node 安装要求；安装程序可选目录。
- 已知限制明示：没有 Steam AppID 的平台功能、没有公网主机时的互联网服务状态、未进行实体跨城测量的网络质量。

## 测试方法边界

生命周期 E2E 使用临时 debug 护盾保持静止探针存活，并从仍活着的 AI 中选取观战夹具。首轮成品验证暴露了访客 / 预选 AI 随机提前阵亡导致菜单断言提前撞上结算的测试竞争，不能通过反复重跑掩盖。临时护盾不进入普通比赛；结算仍由原规则执行。重跑以三轮独立进程验收，并保留结构化错误和原始报告。

桌面性能探针为避免百人 AI 吞掉静止采样玩家而缺少有效样本，使用仅 debug 环境提供的临时护盾；原 AI、食点、物理、渲染照常运行。它测绘制 / 模拟压力，不测难度或真人输赢。结算 / 观战 E2E 通过明确测试夹具设置剩余存活者，再让原规则下一帧实际结算，不直接伪造客户端胜利事件。

真实试玩与自动化各有用途：前者发现布局 / 操作问题，后者保证回归和可复现数值。不能将一台机器的两客户端与 HTTPS 代理测试写成跨城验收，也不能以单机满帧承诺所有公共服务器房间容量。

收尾时发现旧性能探针漏关闭主页。旧短测和屏幕外数字保留为诊断历史，不作为正式版玩家帧率结论；重新验证可见前台对局。程序进入正常比赛时也无条件关闭主页，防止重开 / 测试入口带入覆盖层。源码行为测试和桌面可见性断言共同防止回归。
