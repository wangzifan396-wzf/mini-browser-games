# 合集去同质化与开放工厂升级 SDD

日期：2026-10-23。范围：网页合集策展、评级纠偏与 `tiny-factory.html`；不修改星团大作战 1.0.0 成品，不发布未完成的 FPS 原型。

## 目标与非目标

质量优先，不以新增作品、关卡或测试数量作为产出目标。先区分真正不同的玩家决策，再集中打磨值得维护的代表。共同使用卡片、表格、画布或固定关卡，不构成换皮证据；同一万能解贯穿内容、只有名字变化、系统不参与输赢，才是降级依据。

本轮不是全合集重新试玩，也不承诺商业上市品质。不用没有真人长测支持的评分升级，不将原型包装为大型成熟游戏。

## 流程与冻结规则

1. 只读审查输入 → 状态变化 → 失败反馈 → 再尝试的循环，对比同类更强代表。
2. 用正式规则函数复核重复答案、规则指纹和无效系统；留下带日期、源码摘要的审查脚本。它们是一次性证据，不加入日常 CI 执行废案规则。
3. 更新唯一评级名单 `GAME_TIERS.json`、README、质量审计与离线目录。E 级保留文件、URL、存档及 Git 历史，但退出推荐、活跃目录与默认质量审计；不再补新关卡或包装升级。
4. 先写验收边界，再实现开放工厂的实际问题；通过纯规则、存档、真实界面输入与旧合同兼容检查。
5. 只发布本批文件，排除工作区其他未提交项目；验证 GitHub CI 和 Pages。没有实际跑过的测试不写“已通过”。

`wonder-park` 从 A 降至 C：票价、偏好、容量、清洁确有不同反馈，保留一个公园经营原型，但六园通用参考布局暴露目标过松，不再宣称已充分平衡。其余历史评级本轮没有全量重评，保留不等于再次认证。

## 开放工厂规格

- **公平汇流**：按目的地记住上次成功来源，竞争只在成功传输后轮换，不能被坐标顺序或 tick 奇偶永久饿死。保持每事务至多走一格、容量预约与物料守恒。真实堵塞仍需要玩家改造，不用隐藏全局库存绕过物流。
- **原位配置**：筛选物品与旋转方向分离；配置不收钱、不改变方向、不吞掉货物。
- **暂停搬迁**：选择源与合法目标，成功时整体迁移缓存、产出、加工进度与货物，不卖出重买。无效目标、矿脉不匹配、运行中操作须原子拒绝；Esc 可取消。
- **可解释反馈**：检查器明确区分缺料、输出不接收、拥堵与本轮竞争。若没有采集实际窗口数据，不把理论产率标成实测吞吐。
- **防损坏**：非法方向、非整数和 NaN 在扣钱或修改建筑前拒绝；存档验证新状态，兼容旧开放工区档案。
