# 网页游戏特色更新 · SDD

日期：2026-10-04。范围：现有单 HTML 合集；星团大作战保持当前版本，不在本批改动。

## 1. 问题与目标

现有合集的稳定性审计不能代表可玩性。近期大量作品采用固定合同、固定参考解、三星的同一种结构；题材不同，但探索与重玩空间不足。此次按玩家的核心决策区分作品，不以关卡数量、代码行数或自动化全绿作为乐趣证明。

质量优先于数量，用户明确允许只做一款足够好的游戏。首批以微型流水线开放式深改为主力候选，并修复三款有证据的旧作缺陷；两个不同类型的新作只作为质量验证候选。候选不能因已写完或测试通过就当成品上线，未达标留本地或继续打磨，不填充 README 数量。不是承诺一次重制全部 124 款，也不宣称单文件小游戏达到商业大型 FPS 的品质。

## 2. 设计范围

| 作品 | 玩家主要决策 | 本批验收 |
| --- | --- | --- |
| 微型流水线 | 自主建造、配方、运输、瓶颈与扩产 | 保留旧合同和档案；新增种子自由工区、可建生产设备、研究与无限经营、可定位堵塞 |
| 裂隙行动（新） | 视线、走位、弹药、装备经济、攻防时机 | 原创 2.5D 第一人称离线机器人攻防；地图连通、墙体遮挡、装拆结算与连续回合 |
| 回声禁区（新） | 行动点、敌人意图、噪音、载重、见好就收 | 种子地图、预告攻击、潜入搜刮、撤离结算、失败损失与基地升级；不做固定关卡答题 |
| 孤岛求生 | 生存资源和事件选择 | 有利事件只计一次；非法旧档不崩溃；存储不可用仍能玩 |
| 背包角斗场 | 装备形状、邻接与耐力 | 修正错误冠军、回血周期、专精效果、四方向旋转、战斗期间改包与重复结算 |
| 符文自走棋 | 侦察、经济、站位、羁绊 | 对手情报与实际阵容一致；站位影响接敌与射程；装备不凭空丢失；备战/战斗隔离 |

仅通过完整闭环、操作与质量复核的新作才进入目录，届时先保守列 B 级。不用自动测试替代完整人工试玩授予 S/SS。旧作不因为功能新增而自动升档。

本批发布决定：4 款旧作更新进入原目录；回声禁区放在 `development/`，以明示的可玩测试版公开源码和试玩，暂不评级、不增加正式目录计数；裂隙行动仍留本地开发原型，竞技节奏、机器人和演出不足，不随本批发布。后续只在真实体验门槛满足后转正，不凭测试数量转正。

## 3. 研究依据与原创边界

- [Factorio 物流开发日志](https://www.factorio.com/blog/post/fff-441)：学习增量建设、可诊断瓶颈与库存死锁处理；不复制代码或美术。
- [Into the Breach 官网](https://www.subsetgames.com/itb.html)：学习清晰预告敌人行动，降低无法解释的失败；新作使用自己的行动点、噪音与撤离规则。
- [ZERO Sievert 官方页](https://store.steampowered.com/app/1782120/ZERO_Sievert/)：学习据点整备—搜刮—生还的风险循环；不搬枪械、地图或名称。
- [Counter-Strike 2 官方页](https://www.counter-strike.net/cs2)：学习空间与道具的战术关系；本批不宣称具备其竞技网络、体积烟雾或引擎水平。
- [Backpack Battles 官方页](https://store.steampowered.com/app/2427700/Backpack_Battles/)：学习位置与组合应当真正改变构筑效果，而不是装饰。
- [shapez 开源仓库](https://github.com/tobspr-games/shapez.io)：仅作架构研究。GPL-3.0 代码与资产不混入本 MIT 项目。

以上是设计借鉴，不是对这些作品品质、销量或实现细节的未经证实推断。

## 4. 技术约束

每款交付一个无 CDN、无外部素材请求的 HTML，双击可运行。Canvas/SVG/CSS 原创视觉，离线 PvE 明示。模拟使用秒或离散回合，不随屏幕刷新率改变速度。暂停/失焦释放输入；存储失败不得中断游戏。存档有版本与结构校验；校验码是损坏检测，不是假称安全或作弊防护。

旧游戏修改必须兼容能验证的旧档；无法迁移的布局不得伪造恢复。玩家和测试执行同一套规则。测试入口只帮助观测与构造边界，不维护另一个“必胜玩法”。原有用户未提交的 museum-climate、宣传片及文章文件保留不动。

## 5. 工作流与发布门槛

1. 盘点与复现：记录同质化及真实缺陷，不根据标题猜测。
2. 设计与实现：按互不重叠的文件并行实现，先确保完整胜负/经营闭环。
3. 规则回归：墙体/射程/资源/AP/经济/结算守恒、随机可达、长回合、坏档、重复操作。
4. 后台浏览器验收：桌面和 390×844 触屏真实点击、移动/放置/开火等关键动作，截图复核，捕获脚本与控制台错误；不占用用户前台做长测。
5. 合集验收：旧合同参考仍有效；目录、评级、README 三方一致；本地 file:// 目录能浏览且链接打开本地游戏。
6. 发布：只暂存本次明确文件；检查 diff/外部依赖/敏感数据；提交推送并确认 Pages 部署。未通过的检查修复后重跑；未测试的能力明确标注，不发布为已验证。

实际结果记录在 [本批 QA](browser-games-refresh-qa.md)。后续扩展由真实试玩反馈决定，优先改善决策、反馈与平衡，而不是再增加相同结构的内容数。
